# EMA Crossover Strategy Integration

## Overview

The EMA Crossover strategy has been integrated into the Signals pipeline. This strategy generates trading signals based on Exponential Moving Average (EMA) crossovers, specifically using EMA 12 (fast) and EMA 26 (slow).

## Implementation Details

### Strategy Location
- **File**: `pipe/lib/strategies/ema_crossover.py`
- **Class**: `EMACrossoverStrategy`
- **Strategy Name**: `ema_crossover`

### How It Works

1. **Signal Generation Logic**:
   - **BUY Signal**: When EMA 12 crosses above EMA 26 (bullish crossover)
   - **SELL Signal**: When EMA 12 crosses below EMA 26 (bearish crossover)
   - **HOLD Signal**: When EMAs are aligned or spread is below threshold

2. **Strength Calculation**:
   - **RSL (Relative Strength Levy)**: Ratio of EMA fast to EMA slow
   - **EMA Spread**: Percentage difference between fast and slow EMA
   - **RSI Confirmation**: Optional RSI-based confirmation (enabled by default)

3. **Configuration Parameters**:
   - `min_spread_pct`: Minimum percentage spread between EMAs to generate signal (default: 0.5%)
   - `rsi_confirmation`: Whether to use RSI for additional confirmation (default: True)

## Integration Points

### Strategy Registry
The strategy is registered in `pipe/lib/strategies/__init__.py`:
```python
_STRATEGY_FACTORIES: Dict[str, type[Strategy]] = {
    "stock_mean_reversion": StockMeanReversionStrategy,
    "crypto_momentum": CryptoMomentumStrategy,
    "ema_crossover": EMACrossoverStrategy,  # ← New strategy
    "hold": HoldStrategy,
}
```

### Backend Connection
The backend API automatically serves signals generated by this strategy:
- **Endpoint**: `GET /api/signals/{symbol}`
- **Data Source**: Signals are stored in the `signals` table in PostgreSQL
- **Flow**: `signal_analyzer` flow → `generate_and_store_signal` task → Database → Backend API

## Configuration

### Using Environment Variables

To use the EMA crossover strategy for a specific symbol, set the environment variable:

```bash
# For BTC-USD
export SIGNAL_MODEL_BTC__USD=ema_crossover

# For AAPL (note: use double underscore for hyphens in env var names)
export SIGNAL_MODEL_AAPL=ema_crossover

# For symbols with hyphens, use double underscores
export SIGNAL_MODEL_ETH__USD=ema_crossover
```

### Default Symbol Mapping

Currently, the default mappings are:
- `BTC-USD`: `crypto_momentum`
- `AAPL`: `stock_mean_reversion`

To change defaults, modify `_DEFAULT_SYMBOL_MAPPING` in `pipe/lib/strategies/__init__.py`.

## Testing

### Quick Strategy Test

Run the test script to verify the strategy works:

```bash
python3 test_ema_crossover.py
```

This will:
1. Import the strategy
2. Test strategy retrieval
3. Generate a sample signal with test inputs
4. Display the result

### Full Pipeline Test

To test the complete flow (requires database setup):

1. **Ensure market data is synced**:
```bash
cd pipe
uv run python -m pipe.flows.market_data_sync --symbols BTC-USD,AAPL
```

2. **Run signal analyzer with EMA crossover strategy**:
```bash
cd pipe
export SIGNAL_MODEL_BTC__USD=ema_crossover
export SIGNAL_MODEL_AAPL=ema_crossover
uv run python -m pipe.flows.signal_analyzer --symbols BTC-USD,AAPL --indicator-window 600
```

3. **Verify signals via API**:
```bash
# Check BTC-USD signal
curl http://localhost:8000/api/signals/BTC-USD

# Check AAPL signal
curl http://localhost:8000/api/signals/AAPL

# List all signals
curl http://localhost:8000/api/signals/
```

### Expected Output

When the strategy generates a signal, you should see:
- **Signal Type**: BUY, SELL, or HOLD
- **Strength**: 0-100 score
- **Reasoning**: List of reasons for the signal, including:
  - EMA crossover status
  - RSL value
  - EMA spread percentage
  - RSI confirmation (if enabled)

Example reasoning:
```
- EMA 12 (51000.00) above EMA 26 (49000.00) - bullish crossover
- RSL: 1.0408 (fast/slow ratio)
- EMA spread: 4.00%
- RSI 45.0 confirms bullish momentum (not overbought)
```
